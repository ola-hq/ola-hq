AIOS · FIELD GUIDE

The AI is weird.
Work with the weirdness.

A short field guide to the problems people keep running into — and the practical fixes that usually matter more than fancy prompt tricks.

Running joke, serious point: sometimes the problem is the user. Sometimes the problem is the model. Usually the real problem is the interface between the two.

“It forgot what I already told it.”

Do not assume conversation history equals durable operating state. Save the important truth somewhere reloadable: current state, project record, handoff, or explicit instructions.
“This long thread is getting worse.”

Long threads are useful for exploration but bad as the only storage layer. Compress decisions and current truth, then start fresh when the thread becomes noisy.
“The answer is technically right but boring.”

Compression stripped away the texture. Keep the clean state small, but point it to richer source material so the AI can expand back into specific work.
“I gave it everything and it still missed the point.”

More context is not always better context. Give the model a hierarchy: what matters now, what governs the task, and where deeper material lives.
“I have to organize everything before I can ask.”

You should not. Give messy input, then have the AI extract tasks, facts, decisions, dependencies, and references itself.
“It keeps making duplicate files/projects.”

Tell it to connect before creating. Search for an existing project/topic first; create only when continuity genuinely benefits from a new record.
“It said it saved something, but did it?”

Require verification. Never claim a write, send, upload, or edit happened unless the action actually completed.
“A new chat has no clue what is going on.”

Give fresh chats a startup protocol: load SYSTEM, then CURRENT STATE, then deeper project files only when relevant.
“The workflow tutorial has 37 steps.”

Ask which of those steps the AI itself can perform. Humans define intent, constraints, and approvals; machines should do repetitive organization.
“My system became another chore.”

Kill the ritual. If maintaining the system costs more attention than it saves, simplify it. The smallest structure that preserves continuity usually wins.
“I expected it to keep working on its own.”

Do not assume background behavior. If you need a future reminder or recurring monitor, explicitly use a scheduled feature that supports it.
“I want one AI to know absolutely everything.”

That sounds convenient but often creates mush. Funnel broad context into smaller governing records, then load only the slice needed for the current job.
“It found the right person, but the wrong project.”

An entity can belong to many threads. Resolve the person/pet/place plus the current task and canonical project node before loading deeper context.
“I gave it a reference and it copied the wrong parts.”

Label the reference role. Style donor, photo donor, fact source, layout reference, and DO NOT INHERIT are different jobs. Preserve the exact relationship, then reopen the source before execution.

THE RULE OF THUMB

Do not optimize for the biggest prompt. Optimize for the cleanest reload.

That is the core move behind the Hourglass: rich context can stay rich in the source layers; the reload layer only needs enough structure to find and use it again.
